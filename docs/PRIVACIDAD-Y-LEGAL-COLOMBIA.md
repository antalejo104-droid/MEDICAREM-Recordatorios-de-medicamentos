# MEDICAREM — lista de revisión de privacidad y legalidad en Colombia

Este documento es una lista de trabajo para el prototipo, no un concepto jurídico ni una declaración de cumplimiento. Antes de procesar información de salud real, revisar el diseño con asesoría jurídica y de seguridad competente en Colombia.

## Datos que requieren protección reforzada

Los medicamentos, horarios e historial de eventos pueden revelar información de salud. Tratar estos datos como sensibles, limitar su recolección al mínimo necesario y no usarlos para publicidad, perfilamiento ni recomendaciones automatizadas.

## Pendientes antes de un piloto con datos reales

- Definir claramente quién actúa como responsable y quiénes son encargados del tratamiento.
- Publicar una política de tratamiento de datos y un aviso de privacidad en español, con finalidades, canales de consulta/reclamo, tiempos de conservación y categorías de destinatarios.
- Obtener autorización previa, informada y verificable para datos sensibles; explicar que responder sobre salud es opcional cuando corresponda.
- Definir y documentar el consentimiento del paciente para compartir datos con cuidadores, incluyendo aprobación, alcance, revocación y tratamiento de solicitudes pendientes.
- Diseñar un proceso operativo para consultas, correcciones, revocación y supresión cuando sea jurídicamente aplicable; este prototipo no ofrece todavía una función de cierre/supresión de cuenta de autoservicio.
- Establecer un calendario de conservación y eliminación, copias de seguridad, respuesta a incidentes y control de acceso para personal operador.
- Revisar transferencias y transmisiones internacionales, subencargados, ubicación de datos y contratos del proveedor de identidad, hosting, base de datos y notificaciones.
- Revisar si el uso y las declaraciones comerciales pueden activar obligaciones adicionales como software o dispositivo médico; no afirmar que el producto está certificado o aprobado.
- Evaluar riesgos de accesibilidad, errores de horario, notificaciones ignoradas y dependencia de conexión; dejar claro que la app no sustituye la prescripción ni la orientación profesional.

## Reglas de producto aplicadas

- El paciente controla la aprobación y revocación del cuidador.
- Las notificaciones locales no incluyen nombre ni dosis.
- La ausencia de respuesta se mantiene como **sin confirmar**, no como una omisión afirmada por el sistema.
- El sistema registra una omisión únicamente después de una acción explícita del usuario.
- No se deben usar expedientes reales en desarrollo, capturas, demostraciones ni documentación.

La revisión final debe considerar el texto vigente de la Ley 1581 de 2012, sus normas reglamentarias y cualquier otra disposición aplicable al caso concreto. La lista no sustituye esa revisión.
